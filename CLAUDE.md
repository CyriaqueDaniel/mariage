# Appli RSVP du mariage (21/08/2027)

Formulaire de réponse pour les invités. L'utilisateur débute en code : expliquer simplement, en français.

## Architecture
- Google Apps Script lié à un Google Sheet. Pas de build, pas de npm : les fichiers sont copiés-collés dans l'éditeur Apps Script.
- `apps-script/Code.gs` : serveur (doGet, getInvitation, enregistrerReponse, menu Mariage, création des onglets).
- `apps-script/Index.html` : toute la page (HTML, CSS, JS dans un seul fichier). Elle a un mode démo hors Google (code `DEMO01`) pour tester en local.
- `docs/` : le site invités (GitHub Pages sert ce dossier). `index.html` + `style.css` + `app.js`, sans build. Onglets : Accueil, Infos (questions/réponses de l'onglet « Infos pratiques » du Sheet, question cachée si « Réponse FR » vide), Où dormir (conseil par foyer : `meilleuresFormules` calcule, depuis l'onglet « Tarifs », la formule la moins chère de chaque hébergement selon le nombre d'adultes/enfants du foyer), Répondre. Pas de programme sur le site : il est sur le faire-part. Textes de l'interface dans `TEXTES` (fr, es) de `app.js`, clé absente = français. Langue = choix manuel pour ce code (localStorage `langue-CODE`) > colonne Langue du foyer > langue du téléphone > fr. Dates formatées depuis les paramètres ISO (`iso`, `limiteIso`). Espagnol en tutoiement (« tú »), à faire relire. Le formulaire de réponse est dans `app.js` (section « Onglet Répondre ») : listes reçues du serveur en français, affichées traduites via `VALEURS_ES`, renvoyées en français ; POST texte JSON vers `API_URL`. `apps-script/Index.html` = ancienne page, gardée en secours jusqu'à la mise en ligne. Codes démo fictifs `DEMO01` (fr) et `DEMO02` (es), utilisés aussi tant que `API_URL` est vide. Direction visuelle « fête de village d'été » : vert = demoiselles d'honneur, bleu = garçons d'honneur (provisoire, variable `--bleu`). Décor = bouteilles suspendues par une ficelle de jute, guirlande lumineuse enroulée dedans et bouquet qui sort du goulot (inspiration : photo Pinterest « déco guinguette » fournie par l'utilisateur, non reprise sur le site), verres rouge, orange vif, violet. Plus tard : remplacer par une photo de leur vraie bouteille. Mariés : Morgane & Cyriaque.
- `PLAN-SITE.md` : plan validé du site invités (GitHub Pages, FR/ES). Apps Script y sert d'API : `doGet?action=invitation&code=` et `doPost` (corps texte JSON `{action:'enregistrer'}`). Sans code valide, l'API ne renvoie que `{erreur:'code'}` : pas d'infos sur les invités (noms, codes, allergies) dans le dépôt, qui sera public. Le lieu (Kerpenhir, Locmariaquer) et les réponses des Infos pratiques peuvent y être : l'utilisateur l'a autorisé le 16/11/2026 (pré-remplis dans `installer`).
- Emails d'invitation (`Code.gs`, section « Emails d'invitation ») : textes dans `EMAIL`, versions `un` (1 personne : fr tu, es tú) et `plusieurs` (fr vous, es vosotros) ; salutation avec les prénoms (1er mot) de tous, adultes puis enfants ; objet identique pour tous, envoi par `MailApp` depuis le Gmail du propriétaire. Pour l'instant seul le menu « M'envoyer un email de test » existe (4 versions, liens DEMO01/DEMO02). Prévu ensuite : colonne Invitation envoyée à la fin de « Foyers », envoi programmé le même jour (déclencheur horaire), liens WhatsApp pré-remplis en secours. Moins de 100 foyers (134 personnes) : un email par foyer tient dans le quota Gmail.
- Page d'inscription `docs/inscription.html` + `inscription.js` : chaque foyer saisit adultes et enfants (prénom et nom séparés ; enfant sans nom = nom du 1er adulte), email et/ou WhatsApp (au moins un), adresse postale du foyer obligatoire pour les faire-part (rue, complément facultatif, code postal, ville, pays pré-rempli France/España ; `ENTETES_ADRESSE`, colonnes ajoutées à la fin de « Foyers » et « Inscriptions », code postal en texte). Encadré rouge `.alerte` sous « + Ajouter un adulte » : pas de +1 non prévu. Lien `?cle=…` (clé secrète dans Paramètres « Clé du lien d'inscription », tirée au hasard par `installer`, jamais dans le dépôt), `&lang=es` pour l'espagnol, `?cle=demo` = démo sans envoi. Lien espagnol envoyé = `inscripcion.html` (balises Open Graph en espagnol, redirige vers `inscription.html?…&lang=es`) ; `inscription.html` a les balises en français. Image d'aperçu `docs/apercu.jpg` 1200×630 (bouteilles, prénoms, 21 · 08 · 2027), URL absolue dans `og:image`. API : `doGet?action=cle` et `doPost {action:'inscription'}` → onglet « Inscriptions » (`ENTETES_INSCRIPTIONS`), case piège `site` anti-robot. Menu « Voir les liens d'inscription » et « Ajouter les inscriptions dans Foyers » (doublons par email/WhatsApp/nom d'adulte mis de côté, `FORCER` pour passer outre). « Foyers » a maintenant Email (H), WhatsApp (I, format texte, numéros en +33…), puis Adresse, Complément d'adresse, Code postal, Ville, Pays (J à N).
- Fichiers communs du site : `reglages.js` (`API_URL`), `decor.js` (bouteilles, `dessinerGuirlande`), chargés avant `app.js` / `inscription.js`.
- `GUIDE.md` : procédure de mise en ligne pour l'utilisateur. La tenir à jour.

## Règles
- Un foyer = une ligne dans « Foyers », avec un code de 6 caractères. Une ligne par personne dans « Réponses ».
- Les colonnes de « Réponses » sont lues par position (`ENTETES_REPONSES`) et par les formules de « Synthèse » (lettres A à S). Ajouter une colonne = l'ajouter à la fin et mettre à jour `lireReponse_` et les formules.
- Les listes (allergènes, régimes, transports, covoiturage) sont définies dans Code.gs et envoyées à la page. Le serveur revalide tout dans `nettoyer_`.
- Après une modification, rappeler à l'utilisateur de recopier le fichier dans Apps Script et de publier une nouvelle version du déploiement.
